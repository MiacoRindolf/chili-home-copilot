# Native fractional PAPER cycle journal

An interrupted entry submission must restore a reconciliation action, and an actual partial exit fill must leave a full-sale instruction for the remaining available balance. Whole-share reservations cannot represent this lifecycle. The new pure reducer and PostgreSQL store retain exact native quantities without altering the existing equity quantity contract.

The store serializes reservations with the existing Alpaca action/account lock followed by the adaptive account lock. READ COMMITTED is required: taking a repeatable-read snapshot before waiting could hide a reservation committed by the previous owner. The locked admission callback must cover the other ordinary/adaptive ledgers and supply a fresh native funding read. The store does not certify callback coverage. Admission and pretransport revalidation retain the observed funding identity and arithmetic receipt in the journal.

The current debit bound is the entire frozen limit-buy notional. The risk bound is also the entire notional because this component has not certified a protective stop. Both remain reserved through unknown transport, partial entry and partial exit. Broker reflection is not guessed from timestamps or order status. This deliberately retains possible overlap with broker-reported funding until a separate reflection/settlement contract proves otherwise.

No top-N is used when reading active claims. Two affordable distinct assets can reserve concurrently; insufficient shared funding admits only the affordable subset under the account lock. Another open owner of the same native asset is rejected because independent same-asset lot ownership is not implemented.

The event journal is append only, with transactional exposure projection, unique cycle/client identity, revision CAS and hash-chain replay. Replaying an event ID returns `applied=False`; a caller must never treat that result as fresh permission to POST. A transport intent is persisted before broker submission. After restart, an unresolved intent requests lookup by client ID and never a blind second order.

Full-sale requests bind the exact available native position quantity, the position revision and a supported price grid. Position reads have their own durable identity/revision and are invalidated by a later order observation. Entry orders must be terminal before exit sizing; a pending exit must be terminal before another position read can authorize a new full-sale request. An actual partial IOC sell therefore leads to reconciliation and a new full-residual sell. Flat exposure requires terminal orders and an explicitly bound native position read; it does not certify settled fees or P&L. A positive entry followed by unexplained flatness, without any known exit fill, remains unresolved.

Migration385 creates the tables and event guards. It creates no cycle, submits no order and starts no worker. The API requires explicit engineering bounds for event storage and lock waits; they are not strategy windows. Tests use their own UUID-named schemas on isolated DB26 only.

Production activation remains unfinished. The execution owner must provide authenticated raw broker reads, exact PAPER/lease authority, full ordinary/adaptive coverage under the account lock, tick entry/exit decisions and continuous reconciliation. Existing equity posture certification must recognize fully owned native crypto exposure before mixed trading is enabled. USD funding is supported here; non-USD quote assets require their own inventory/ownership ledger. There is no crypto short support and no automatic trading activation in this change.

Do not approximate the cross-asset funding seam with ordinary buying power. Alpaca distinguishes crypto non-marginable funding from the margin account buying-power formulas; the correct ordinary/native reflection bridge remains separate work.
