# Native crypto execution owner — integration in progress

The execution owner now connects the exact fractional cycle journal to a literal Alpaca PAPER HTTP client. It can submit a frozen native limit entry, reconcile by order/client identity after interruption, cancel and reconcile an unfinished partial entry, refresh the native position, and submit a limit IOC for the entire available residual balance. It does not manufacture a tick entry or exit signal.

One PostgreSQL session lock serializes transport for each account/cycle. Unrelated cycles have distinct locks; the shared account-budget lock is held only for reservation/event transactions. The per-cycle lock connection is discarded on exit so a session lock cannot leak into the pool. The literal pre-HTTP check detects loss of that lock. A separate `PaperWindowAuthority` binds the current application process to its real parent supervisor, accepted receipt, unchanged supervisor/environment files and the actual held ALPA/OWNR database lease. That class cannot start or elevate another process. Its receipt is ownership evidence, not an independent grant of trading permission.

Raw request/response bytes are retained in append-only cycle events before response interpretation. Malformed data, HTTP errors, resource truncation and unknown transport remain distinguishable. No redirect, LIVE endpoint override, credential fallback or automatic POST retry exists. The fixed credential client reads and matches the account UUID before economic mutation. Credentials are omitted from journal metadata and any credential echo is refused.

The owner rechecks the tick entry decision after the budget/intent commit and immediately before HTTP. An important liveness distinction is explicit: if a gate failed before entering the HTTP opener, the durable `not_transported` evidence can close a proven-unsent entry or allow a fresh full-balance exit attempt. Once the opener was entered, errors are unknown outcomes and never use that release path. A client-ID lookup404 cannot prove an earlier POST was unsubmitted.

New cycles use `native_crypto_long_cycle_v2` to bind transport intent revisions. Historical v1 entry/exit events keep their previous replay shape; the new transport owner refuses an active v1 cycle rather than silently upgrading its meaning. The deployed journal was empty before this integration work. A successful cancel request is not a terminal fill; a fully filled exit order is not itself a flat-position certificate. Each full-sale attempt refreshes the actual available balance, including after an actual partial fill. Closed exposure does not claim settled fees or P&L.

Tests exercise the actual owner, HTTP boundary and PostgreSQL store against a deterministic external broker fixture. They cover full-residual sale after partial fills, accepted-POST/lost-response restart, repeated CID404, missing/invalidated ticks, partial-entry cancellation, reserved balance, lost ownership, same-cycle fencing versus unrelated-cycle access, raw malformed evidence, definitive local unsent proof, and window/lease identity failures. The HTTP path was also cold-started against the real PAPER GET/account endpoint with a hard GET-only wrapper; that read succeeded without loading application settings. No order was sent by that probe.

This is still an unfinished integration branch. Before automatic trading is enabled, the host must supply the complete ordinary/adaptive/native admission and ownership bridge and a real shared tick decision source, then wire native lifecycle wakeups into the running application. A funding reader invoked under the store's account lock must not recursively append through another store connection: retain its GET evidence in the same admission receipt/transaction, or use an independent durable raw journal, to avoid self-deadlock. The existing equity posture rejects crypto positions and equity reservations do not yet charge native claims, so merely providing a native callback is insufficient.

Other concrete integration work: native full-universe quote/trade source coverage; native balance/increment behavior for fee-adjusted residuals verified on PAPER; explicit broker rejection reconciliation; broker position/order ownership reconciliation; shutdown/restart behavior across the existing supervisor window; and non-USD quote-asset funding. None is certified by the owner tests or a successful account GET. No new backside strategy or shorting is activated here.
